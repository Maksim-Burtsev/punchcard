# Calibration on real open-source PRs — August 2026

Punchcard's constitution was built from books and verified on synthetic
fixtures. That proves it catches planted flaws; it says nothing about
whether it stays quiet on good code. So it was run against six real Python
pull requests, and every factual claim it made was checked — by reading the
repositories, and where possible by executing the code.

## The set

Chosen for spread, not for flattery. Three PRs merged by maintainers of
well-run projects (where the honest review is mostly silence), and three
closed ones.

| PR | Outcome | Why it's in the set |
|---|---|---|
| celery/celery#10485 | merged | Security fix: masking credentials in broker alternates |
| celery/celery#10493 | merged | Subtle correctness fix in timeout handling; the diff is provably a no-op removal |
| pydantic/pydantic#13680 | merged | Larger internal redesign of serialization schema plumbing, 8 files |
| Textualize/rich#4142 | closed | Closed under an AI-contribution policy, **not** for code quality — quality unknown |
| tiangolo/sqlmodel#2036 | closed | Same: flagged as AI-generated by a bot; quality unknown |
| samuelcolvin/arq#462 | closed | Real ground truth: maintainer said "should be in a separate repo"; codecov reported 0% patch coverage on ~192 new lines |

Each PR was applied on top of its merge base as uncommitted changes, so the
skill worked exactly as it does locally and read the project's real
surrounding code.

## What it found

The headline claims held up under adversarial verification. Auditors
re-executed them rather than re-reading them:

- **celery#10485** — the merged fix closes half the leak it names. `broker.alternates` is scrubbed, but the sibling `hostname` field still carries credentials for every kombu transport with `can_parse_url = True` (mongodb, sqlalchemy, azureservicebus, azurestoragequeues, gcpubsub). Confirmed by running kombu directly. This survived every round of adversarial checking.
- **arq#462** — the maintainer's actual objection (this doesn't belong in the package), plus unauthenticated routes rendering job args, kwargs and results; a Redis pool per request, never closed; a `KEYS` scan per page. Confirmed by building the wheel: `arq/ui.py` ships in it while the metadata declares neither fastapi nor fastui, so `import arq.ui` is an ImportError for every installer.
- **rich#4142** and **sqlmodel#2036** — regex span arithmetic and a silently dropped `unique=True` constraint, both confirmed by execution on the patched trees.

Across seventeen findings in the first round there was **not one comment on
naming, formatting, import order or style**. The altitude lock held.

## What was wrong — and what it changed

The first round exposed four systematic problems. Each produced an edit to
the skill or the constitution, and each edit was verified by re-running.

| Problem | Evidence | Fix | Verified |
|---|---|---|---|
| BLOCKER inflation | Blocked pydantic#13680 — merged by a core maintainer — over behavior the diff's own comment documents as intended | A documented decision is a `QUESTION`, not a BLOCKER; a verified consequence is never a QUESTION | Re-run: 0 BLOCKERs, non-blocking verdict, objection filed as QUESTION |
| Unrunnable test claims | Asserted a test "would still pass" if the change were reverted. It would not — the reviewer stopped reading before the assertions that refute it | Claims about test behavior are experiments: run them or don't make them | Re-run: claim gone, coverage claims only |
| The cap hid the point | On arq#462 — 192 new lines, zero tests, cited by the maintainer — a slot went to a devcontainer file and the missing test was never mentioned | Missing tests for a new module/route/public function is mandatory, filed separately, exempt from the cap. "It's only a POC" is the author's answer, not the reviewer's assumption | Re-run: present in both runs, with two specific missing cases named |
| "Wrong shape" never fired | On arq#462 it said "fix these four and merge" while its own top finding was "this belongs elsewhere" — telling the author to keep building | Mechanical trigger: wrong package/service/repo, or a central mechanism needing replacement, is that verdict | Re-run: "Wrong shape. Talk before more code." — matching the maintainer |

Four smaller tendencies were also corrected: piling three principle
citations into one finding, demanding a pattern the codebase itself doesn't
use (it asked celery to abandon a mocking style that is the house
convention), line anchors drifting from their snippets, and never once
saying "Ship it." — six reviews, six non-empty finding lists.

That last one turned out to matter most: after the edits, **celery#10493
came back as a clean "Ship it."** — a no-op deletion correctly recognized as
needing nothing from a reviewer.

## Known limits

Honest accounting of what did not get fixed.

- **Fix lines are the weak spot.** Across the final four runs, two to three
  fix suggestions per review were incomplete or would break a case the
  current code handles. The claims are verified; the prescriptions often are
  not. The last edit narrows the Fix line's contract to direction plus
  constraint unless the recipe was traced — untested at the time of writing.
- **Supporting sentences lag the headline.** Central claims verify; the
  reinforcing ones sometimes carry an enumeration short by one, or an
  inflated count. Numbers should be exact or absent.
- **Verdict variance between runs.** Two runs of arq#462 produced "Wrong
  shape" and "Ship after" from near-identical finding sets. The trigger is
  now explicit, but ranking is a judgment call and it wobbles.
- **A weak finding survived every round.** It kept asking celery to build a
  real `kombu.Connection` instead of a mock, though the project mocks it the
  same way elsewhere — the reviewer grepped, found a usage supporting its
  case, and cited that. Motivated reasoning is not easily prompted away.

## Reproducing

Every PR is public. Apply it on its merge base as uncommitted changes and
run `/punchcard`:

```bash
git clone --filter=blob:none https://github.com/samuelcolvin/arq.git
cd arq && git fetch origin pull/462/head:prhead
git checkout "$(git merge-base HEAD prhead)"
git diff HEAD prhead | git apply
```
