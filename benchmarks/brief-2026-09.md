# The brief on Sonnet 5, two rounds — September 2026

Every measurement before this one scored a review: findings against a
verified union, a verdict against the upstream outcome. `/punchcard:brief`
produces neither. It hands the reviewer a model of the change before the
review — what it claims, a before/after map of the flow it changed, a
before/after table of what holds, the hunks where the behavior is chosen —
and the questions are different: does the map exist and is it grounded, are
the hunks real code at real lines, does the table say what a reviewer needed
to be told, and does the brief hold its own law — no findings — on a change
where a finding is the easy thing to write. This is the first measurement
of that, on the model the [three-way benchmark](three-way-sonnet-2026-08.md)
established as the harsh one.

## Protocol

Twelve public PRs, one skill, one model. Round one: eight PRs, two cold runs
each, plus one run of the Russian-prompt variant — **17 runs**. The skill
was corrected on what round one showed and round two repeated the eight,
added four PRs no fix had seen, and repeated the Russian run — **21 runs**.
Two rounds was the ceiling set before the campaign started, so what round
two still shows is reported as a limit, not fixed.

All runs on `claude-sonnet-5` at effort `medium`, via `claude -p` (CLI
2.1.257), `--output-format json` for cost, time and token capture,
`--plugin-dir` pointing at the checkout of this repository, the working
directory a scratch folder that is not a git repository, so the brief had no
local diff to confuse with the target. The prompt was the command itself:

```
/punchcard:brief https://github.com/<owner>/<repo>/pull/<n>
```

and, for the Russian run, `Сделай /punchcard:brief <url>`. No repository was
cloned: the brief fetched the diff and the description with `gh` and read
files it needed at the PR's head sha through the API, which is the situation
the command is written for.

Every run passed `--settings` disabling the three user-scope plugins on the
host (`ponytail`, the installed `punchcard`, `superpowers`), and the
skill-list probe before the first run showed only the three commands from
`--plugin-dir`. Two things could not be isolated and applied to every run
equally: a user-level `~/.claude/CLAUDE.md` (the same deviation the
[corpus-expansion](corpus-expansion-2026-08.md) campaign declared) and three
user-level skills unrelated to code review.

Two runs per PR because a single Sonnet observation cannot tell a skill gap
from noise: a violation on 2/2 runs is systematic, on 1/2 it is flaky, and
every PR yields a determinism pair.

## Pre-registered

Before any run was read, each PR got a file from my own reading of its diff:
the decisions a reviewer must be handed (D1…Dn — the places where behavior
is chosen), the invariants that changed (I1…In), the altitude the map has to
be drawn at with an expected node-count band, and the promised behavior with
its class. Recall below is against those lists, matched by mechanism, never
by wording. A decision a run showed that I had not listed was checked against
the diff and, when real, extended the list for every run; a hunk that was
plumbing, test code or code from outside the repository counted as a content
violation instead.

The lists, condensed:

- **celery#10534** — D: the one line (`LRUCache` for `{}`); the code whose
  meaning changed (`pop` → `KeyError` → `pass` now covers an evicted key). I:
  bounded size; orphan keys evicted; a late parent no longer collects its
  children; LRU order. Map: state shape, 4–8 nodes.
- **celery#10524** — D: `if not ids: break` ahead of the deadline; `timeout
  is not None` for the falsy zero; the nap clamped to the remaining budget and
  time accumulated from actual sleeps. I: six rows from `timeout=0` to
  `max_iterations` no longer feeding the deadline. Map: loop body.
- **starlette#3431** — D: seven, from where the app-level limit sits in the
  stack to `except BaseException` in the multipart parser; the central one is
  that a nested limiter does not wrap again but retunes the active
  responder's ceiling. I: eight. Map: middleware stack, 6–14 nodes.
- **pydantic#13742** — D: trailing zeros stripped by hand instead of
  `normalize()`; an exponent that does not fit `i64` saturates; one call
  returns both counts; the Python fallback restructured the same way. I: four.
  Map: the computation's flow.
- **starlette#3438** — D: the per-request provider and reentry guard; the

  dispatch; the `send` wrapper setting status and error. I: seven. Map: call

- **django#21733** — control. D: none. I: none. Map: one sentence. Expected
  total: about ten lines, no hunk.
- **zod#6530** — D: seven, from the three-valued walk answer that is never
  cached when assumed, to the builders copying shapes per key. I: six. Map:
  the cycle walk's call flow, 5–12 nodes.
- **pydantic#13634** — D: six, including the unrelated Windows recursion-guard
  bump in the same diff. I: seven. Map: module graph, 6–12 nodes.
- **airflow#71756, poetry#10944, aiohttp#13613, aiobotocore#1587** — written
  before round two on the same terms; poetry's list notes that the
  description covers one of two commits and the map has to show the second

## Scoring

Per run, in the tables below:

- **D**, **I** — recall against the pre-registered decisions and invariants.
- **alt** — the map is at the pre-registered altitude and within the node
  band.
- **content** — violations of the skill's own content gates: the claim
  compares, retells or explains the class; a row about signatures or tests; a
  conclusion in a cell; a hunk that is test code, out-of-repo code or
  plumbing; prose under the map fence; the wrong language.
- **format** — a preamble before the header, a title repeated, an anchor
  that does not resolve, a hunk in diff syntax, a map wider than ninety
  columns.
- **leak** — sentences that grade, recommend or name a defect, from a
  banned-word grep adjudicated by hand.
- **copied** — hunks whose every non-blank line (arrow notes stripped,
  whitespace normalized) appears contiguously in the diff or in the captioned
  file at head sha. Scripted; a hunk that elides a comment line in the
  middle counts as not copied.
- **anchored** — captions whose `path:line` resolves: the file at head sha
  contains the hunk's first line within two lines of the number. Scripted.
- **words**, **$**, **min** — the render's length, the billed cost, wall
  clock.

## What changed between rounds

One commit, `9f6256c`, named for the runs that forced each line:

- **Line numbers.** The caption's number is defined: the hunk's first line
  in the file at the change's head, read off the fetched file or computed
  from the `@@ -a,b +c,d @@` header, and the path repository-relative.
- **No preamble.** The reply is the brief and nothing else, header line to
  last fence.
- **Language.** The brief is in the language the request was written in,
  titles excepted — stated with the Russian case as the example.
- **Mechanical changes.** Every section is one line; a hunk illustrating a
  pattern repeated across fifty files is not a decision; a row about what
  the sweep did not regenerate is a finding.
- **Under the map, the next title.** A paragraph explaining the drawing is
  the drawing failing.
- **The class is a word and a full stop**, nothing in parentheses.
- **A hunk is code at head**, never a `+`/`-` fragment, and copied whole —
  a comment line in its middle stays.

The second number in "copied" is the loose count: hunks whose every line

invented ones.

What changed, and what did not:

- **Anchors.** Round one: ten of seventeen runs carried diff-position line
  numbers. Round two: two of twenty-one (starlette#3438 b, zod#6530 b), and
  seventy-two of eighty-three captions resolve to within two lines of the
  hunk in the file at head. Defining the number was enough.
- **The control.** 141 and 118 words, no hunk, no row, the one-sentence map
  — the five-line brief the skill describes. The finding about `.mo` files
  is gone.
- **Under the map.** One sentence in one run, against three paragraphs in
  round one. **Diff-syntax hunks:** none. **The class in parentheses:**
  none. **Leakage:** none in twenty-one runs by the grep, none by my
  reading.
- **The preamble did not go.** Seven of twenty-one replies still open with
  a sentence before the header — "Now I have exact line numbers. Rendering
  the brief." — and on the control it grew into a paragraph of reasoning.
  The rule is in the output section and in the checklist; Sonnet reads it
  and does it anyway about a third of the time.
- **The Russian request got an English brief again**, 2/2. The prompt was
  one Russian verb around an English command, `Сделай /punchcard:brief
  <url>`; the skill now names that case explicitly and the model still took
  the command's language. A probe with a fuller Russian sentence is
  recorded below.
- **The title repeated per hunk** on three runs (celery#10524 b,
  starlette#3431 a, starlette#3438 b) — "**The decision** —" as the caption
  of every hunk. The skill says the title appears once; it did not say what
  a caption looks like instead, and that is a wording to fix, not a

- **The test-only PR was over-briefed.** aiohttp#13613 changes nothing but
  a benchmark; the brief showed the new test as a hunk and tabled the test
  helpers. "Test code is never a hunk" was written for tests next to

## After round two

Three wordings went in after the last counted run, in `deb027d`, each
named for the runs above: the language of the brief is the language of the
user's own words around the command, said in the skill and — for the first
time — in the command wrapper, which is the text a one-shot invocation
expands to and which had carried no word about language; a caption is a
sentence about what the hunk decides and never the section title again;
a diff that is only tests or benchmarks is a mechanical change.

Two rounds was the budget, so these were checked by probes, not a round.
Before the change, a fuller Russian sentence — "Введи меня в курс дела по
этому PR, мне его сегодня ревьюить: /punchcard:brief <url>" — still got an
English brief (3/3 English across the campaign). After it, the original
prompt `Сделай /punchcard:brief <url>` on celery#10534 got a Russian brief
under English titles, 160 words, no preamble, $0.22. One probe is one probe;
the rate is not measured.

## Verdict on the brief

What the numbers support: on Sonnet 5, briefed by URL with no checkout, the
brief finds nearly every decision a reviewer would have had to find by
reading the diff (85/86), draws the map at the right altitude (20/21), keeps
its own law (0 findings in 21 runs, on a set that includes a control built
to tempt one), and copies real code at real lines (72/83 anchors, no invented
hunk). A one-line change costs a fifth of a dollar and two minutes; a
thirty-file Rust change under seventy cents and four.

What they do not support: a clean render every time. About a third of
replies carry a stray sentence before the header. A request that is an
English command with a Russian verb in front of it is answered in English.
Two runs in twenty-one still numbered their hunks by diff position. Hunks
on heavily commented code lose comment lines from their middle. And a
diff that is only tests gets briefed like production code.

The first two are the ones a user sees. The language one has a wording fix
that held on a single probe after the campaign; the preamble has none that
held — Sonnet reads the rule and overrides it — and the fix that would
settle it is a measurement of its own.
